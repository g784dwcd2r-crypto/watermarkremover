# API reference

The authoritative reference is generated by FastAPI and served by the running
application:

- **OpenAPI document** — `GET /openapi.json`
- **Swagger UI** — `/docs`
- **ReDoc** — `/redoc`

This page is the map: what exists, and the conventions that apply everywhere.

## Conventions

### Authentication

A successful sign-in sets two cookies:

| Cookie        | Flags                                | Purpose                                       |
| ------------- | ------------------------------------ | --------------------------------------------- |
| `ars_session` | `HttpOnly`, `Secure`, `SameSite=Lax` | Opaque session token; only its hash is stored |
| `ars_csrf`    | `Secure`, `SameSite=Lax`, readable   | Double-submit CSRF token                      |

Every unsafe method (`POST`, `PUT`, `PATCH`, `DELETE`) must echo the CSRF cookie
in an `X-CSRF-Token` header. Requests are sent with credentials.

### Errors

One envelope everywhere, including request-validation failures:

```json
{
  "error": {
    "code": "protected_region",
    "message": "The selection overlaps an artist signature. …",
    "details": { "overlaps": [] }
  }
}
```

Switch on `code`, never on `message`.

| Code                      | Status | Meaning                                                       |
| ------------------------- | ------ | ------------------------------------------------------------- |
| `unauthorized`            | 401    | Sign in                                                       |
| `forbidden`               | 403    | CSRF failure, or a password confirmation is required          |
| `consent_required`        | 403    | The project has no ownership attestation                      |
| `not_found`               | 404    | Missing — or someone else's, which is deliberately identical  |
| `validation_error`        | 422    | Request or file validation                                    |
| `unsupported_format`      | 422    | The stored bytes are not a supported image                    |
| `image_too_large`         | 422    | Byte or pixel budget exceeded                                 |
| `invalid_mask`            | 422    | Empty, mis-shaped, or covering almost the whole image         |
| `protected_region`        | 422    | Attribution content in the selection. **No override exists.** |
| `protected_region_review` | 409    | Ambiguous content. Clearable with an explicit attestation.    |
| `job_in_progress`         | 409    | A job of that type is already running                         |
| `job_not_cancellable`     | 409    | Already finished                                              |
| `job_not_retryable`       | 409    | Only failed or cancelled jobs can be retried                  |
| `rate_limited`            | 429    | `details.reset_after_seconds` says when to try again          |
| `internal_error`          | 500    | Nothing was completed                                         |

### Idempotency

Job endpoints accept `idempotency_key`. Repeating a request with the same key
returns the original job rather than queueing the work twice.

### Signed URLs

Upload and download URLs are minted on demand with a short TTL
(`ARS_SIGNED_URL_TTL_SECONDS`, 5 minutes by default). They are never cached, and
never written to logs.

## Worked example: a cleanup, start to finish

```bash
API=http://localhost:8000
JAR=/tmp/ars.cookies

# 1. Register. The response carries the CSRF token; the cookies land in the jar.
CSRF=$(curl -s -c $JAR -X POST $API/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"artist@example.com","name":"Artist",
       "password":"correct-horse-battery-staple",
       "accept_terms":true,"accept_authorized_use_policy":true}' | jq -r .csrf_token)

auth=(-b $JAR -c $JAR -H "X-CSRF-Token: $CSRF" -H 'Content-Type: application/json')

# 2. Create a project.
PROJECT=$(curl -s "${auth[@]}" -X POST $API/v1/projects \
  -d '{"name":"Backdrop cleanup","project_type":"cleanup","retention_days":7}' | jq -r .id)

# 3. Reserve an upload and PUT the bytes straight to storage.
INIT=$(curl -s "${auth[@]}" -X POST $API/v1/projects/$PROJECT/assets/uploads \
  -d '{"filename":"photo.png","content_type":"image/png","byte_size":204800,"asset_type":"source"}')
curl -s -X PUT "$(jq -r .upload.url <<<"$INIT")" \
  -H "Content-Type: image/png" --data-binary @photo.png

# 4. Complete the upload. Without ownership_confirmed this returns 422.
curl -s "${auth[@]}" -X POST $API/v1/projects/$PROJECT/assets/uploads/complete \
  -d "{\"asset_id\":\"$(jq -r .asset_id <<<"$INIT")\",\"ownership_confirmed\":true}"

# 5. Save a mask, then check it before spending a job on it.
VERSION=$(curl -s "${auth[@]}" -X POST $API/v1/projects/$PROJECT/masks \
  -d '{"editor_state":{"version":1,"image":{"width":1200,"height":900},
       "regions":[{"id":"r1","type":"rect","x":60,"y":800,"width":260,"height":48}],
       "adjustments":{"expand":1,"feather":3,"blur":0}}}' | jq -r .version)

curl -s "${auth[@]}" -X POST $API/v1/projects/$PROJECT/masks/$VERSION/preview | jq .protection

# 6. Queue the cleanup and follow it.
JOB=$(curl -s "${auth[@]}" -X POST $API/v1/projects/$PROJECT/cleanup \
  -d "{\"mask_version\":$VERSION,\"mode\":\"fast_fill\",\"mask_approved\":true,
       \"idempotency_key\":\"run-1\"}" | jq -r .id)

curl -N -b $JAR $API/v1/projects/$PROJECT/jobs/$JOB/events

# 7. Export. Resolution, colour profile and metadata are preserved.
curl -s "${auth[@]}" -X POST $API/v1/projects/$PROJECT/exports -d '{"format":"png"}' | jq .download_url
```

## Progress events

`GET /v1/projects/{id}/jobs/{job_id}/events` is a Server-Sent Events stream.

```
retry: 2000

event: progress
data: {"job_id":"…","status":"running","progress":0.42,"message":"Synthesising texture"}

event: done
data: {"job_id":"…","status":"succeeded","progress":1.0,"result":{…}}
```

The stream closes on the terminal event, on client disconnect, or after a
server-side cap. Because progress is read from the job row rather than held in
memory, a client that reconnects sees current state immediately.
